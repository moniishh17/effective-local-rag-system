# effective-local-rag-system

A local, privacy-first Retrieval-Augmented Generation (RAG) system built from scratch in Python. Ask natural language questions over your own documents and get grounded, cited answers — with zero API costs and zero data leaving your machine.

## What it does

This project lets you:
1. Ingest plain text documents into a searchable vector database
2. Ask natural language questions about those documents
3. Get answers generated by a locally-run LLM, grounded strictly in the retrieved content
4. See exactly which source document each answer came from

No cloud API required. No data sent anywhere. Runs entirely on your own machine.

## Architecture

**Ingestion pipeline (`ingest.py`)**
- Reads `.txt` documents from a `docs/` folder
- Splits them into paragraph-aware chunks (avoiding mid-sentence or mid-idea breaks)
- Stores chunks in a persistent [ChromaDB](https://www.trychroma.com/) vector database using sentence embeddings
- Uses `upsert` logic keyed by document and chunk ID, so re-running ingestion after editing a document cleanly replaces old chunks instead of duplicating them or requiring a full database wipe

**Retrieval + generation pipeline (`file.py`)**
- Takes a user's question
- Performs semantic similarity search against the vector store to find the most relevant chunks
- Assembles retrieved chunks into context
- Passes that context to a local LLM (via [Ollama](https://ollama.com/), running Llama 3.2) with a strict grounding prompt instructing it to answer only from the provided context
- Returns the answer along with the exact source file(s) it was derived from — determined in code, not left to the LLM to self-report

## Notable design decisions

- **Hallucination resistance, tested empirically.** The system was stress-tested with adversarial questions designed to tempt the model into fabricating plausible-sounding but false answers (e.g. asking for a well-known character's surname, or a detail similar to something else in the source text). It correctly declines to answer rather than blending in outside knowledge, across multiple different source documents.
- **Reliable source attribution.** Rather than asking the LLM to report which sources it used (unreliable for small local models), the source list is tracked and appended in code — guaranteed correct every time.
- **Idempotent ingestion.** Re-running `ingest.py` on edited documents safely replaces old content instead of duplicating it, using a delete-then-upsert pattern keyed by filename.
- **Fully local.** No OpenAI/Anthropic API costs, no external data transmission — uses open-source embeddings and an open-weight LLM running locally via Ollama.

## Tech stack

- **Python**
- **ChromaDB** — vector database and embeddings

## Setup

1. Clone this repo:
   ```
   git clone https://github.com/YOUR-USERNAME/effective-local-rag-system.git
   cd effective-local-rag-system
   ```
2. Create and activate a virtual environment:
   ```
   python -m venv venv
   venv\Scripts\activate
   ```
3. Install dependencies:
   ```
   pip install chromadb ollama
   ```
4. Install [Ollama](https://ollama.com/download) and pull a model:
   ```
   ollama pull llama3.2
   ```
5. Add your `.txt` documents to the `docs/` folder
6. Ingest your documents:
   ```
   python ingest.py
   ```
7. Ask questions:
   ```
   python file.py
   ```

## Known limitations

- **Inference latency.** Running locally trades speed for privacy and cost — responses take longer than a cloud API, especially on the first query of a session while the model loads into memory.
- **Pure semantic retrieval.** Currently relies on embedding similarity alone; doesn't yet combine keyword-based (BM25) matching, which can miss exact-term queries (specific names, rare terms) that semantic search sometimes underweights.
- **No reranking step** between retrieval and generation yet.

## Roadmap

- [ ] Formal evaluation harness to measure retrieval precision and answer faithfulness systematically
